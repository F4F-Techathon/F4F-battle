# 3D demo 对照需求差距评估

评估日期：2026-10-16（Asia/Shanghai）。需求基线：本次用户贴入的《餐馆推销官：3D 角色资产需求与实现方案》。排除真实 multiagent、餐馆检索/筛选、对话生成和 TTS 服务实现；保留 3D 事件适配、预录音频/时间线驱动和测试文本全流程的验收要求。

## 判断

当前是可用的三人 3D 资产与表演技术样机。距离文档的 P0 演示验收，工程上约完成 40–50%，仍有约一半以上工作；这是按功能、视觉和交付质量综合判断的粗估，不能把它理解为自动测试覆盖率或精确工期比例。G3「测试文本跑通六阶段」目前还未达到。

最值得保留的是 Hyper3D → Blender → GLB → Three.js 的实际链路、三个已绑定角色、动作切换、音频时钟与打断、事件去重/会话隔离、调试 UI。主要欠缺是图形化脸部系统、完整分镜状态机、表演丰富度，以及角色造型与新设定的一致性。

agent-studio 的导演台使用 SVG 的 window.RIG.Actor，不是这里三个 GLB 角色。它的丰富表情、口型、视线、反应、逐字气泡可以借鉴和迁移，但不能计为 3D 已完成。资产页的 model-viewer 目前负责单模型预览和动作播放，未接入导演台表演编排。

## 六阶段还差什么

| 阶段 | 当前 | 验收所需补齐 |
|---|---|---|
| 0 需求收集 | 初始直接三人在舞台上 | 地图全景、角色隐藏、一个 mock 需求输入入口 |
| 1 筛选出场 | 固定三个店铺位置、缩放出现、跑到站位 | filter_done 坐标、候选/淘汰图钉、跳出、曲线路径、真正汇合点 |
| 2 亮相 | 没有独立亮相阶段 | 地图转舞台、依次签名动作、名牌 |
| 3 推销拆台 | 三句固定音频轮流播放，简化的后置反应 | utterance 的 target/reactions、持续说话循环、听众转头/点头、表情特效、九嘴型、说话者镜头 |
| 4 追问 | 文本框只控制当前人物说一句 | mock user_input + focus，让三人按偏好做相关反应并可继续对话 |
| 5 结果 | selection.confirm 只让赢家庆祝 | 用户可操作的选人入口、落选表情/动作、礼貌退场、镜头和重播 |

真实智能体并不是以上任何一项的前置条件。一个本地 fixtures 脚本就能驱动六阶段，用户输入也可以先走确定性的 mock 响应。

## 建议的补齐顺序

1. 先把阶段状态机、四类事件适配器和一段完整 mock 剧本接好，让阶段0→5、取消和重播可演示；复用现有三个GLB，不等后端。
2. 优先做脸：9种P0表情、9种嘴型、特效；将SVG导演台现有表情/反应/逐字气泡的设计和枚举迁移到3D贴图层。说话时嘴层独占、停顿闭嘴，眉眼继续表达情绪。
3. 补说话A/B与倾听的持续循环，目标指向、落选失落和三位真正签名动作；再补三个道具。
4. 分离地图和舞台，补镜头、名牌、结果和退场。
5. 验证穿模、长台词、连续回合、中断重播，完成压缩与目标设备彩排。
6. 若严格采用新设定，单独安排角色造型收敛与重绑，不把「细节更多」作为合格标准。

工作量粗估（有效人日，非交付承诺）：保留当前人物造型，完成可演示P0约5–8人日；严格对齐新造型、三道具、全部19种动作语义及P1，约10–15人日或更多。美术审看轮次、是否重生角色、权重修整质量是主要不确定项；其中一部分可并行。未包含真正multiagent和TTS服务开发。

## Hyper3D 应该怎么 refine

最合适的是生成缺失的独立道具，或在设计收敛后生成更符合矮胖/高瘦轮廓、无五官脸的角色底模。场景小件也可以生成；图钉、圆台、名牌仍适合代码制作。

当前已连接的 Hyper3D 工具提供文/图生模型和BANG拆件，没有「把当前带骨骼GLB局部修形并保留现有蒙皮/动作」的工具入口。因此重生角色要另存v2，并重新完成绑定/权重/动画导出与浏览器验证；不能覆盖现有可运行模型后直接当作升级完成。核心缺口（表情贴图、嘴型、事件、镜头、动作编排）仍需网页和Blender侧实现。

本次没有额外发起付费生成：检查结果支持先修上述结构性缺口，随后对具体道具或明确造型偏差定向生成。可用工具也未暴露TAPose参数，当前只能在提示词里描述A-Pose；若必须显式控制TAPose，需要账户网页或完整API流程。

参数核对：Hyper3D官方Gen-2.5文档支持最多5张输入、TAPose、Quad、texture_delight；Quad medium目标18,000面，不代表导出只有18,000三角形。对于此低细节卡通项目，提高生成档位不会自动解决表情和表演问题。原文对Texture Delight的统一开启建议应结合参考图是否带高光/烘焙阴影决定，官方当前建议按具体光照需求使用。

官方依据：https://docs.hyper3d.ai/en/api-specification/rodin-gen2-5
