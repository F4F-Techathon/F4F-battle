# 餐馆小剧场：具身多智能体选餐体验

## 1. 可复用的项目描述

我们计划开发一个面向餐馆选择的桌面网页原型，将候选餐馆具象化为具有鲜明个性、面部表情和身体动作的 3D 人物。系统首先由一名中立的引导智能体了解用户的初步需求，包括菜系、预算、距离、环境、同行人数及其他限制，并从餐馆数据中筛选出 Top-k 个候选项。当前原型取 k = 3。

三名餐馆代表从地图上的各自位置出现，沿路径跑到同一个讨论区域，轮番展示卖点，并围绕彼此的实际差异进行轻松、幽默的质疑和回应。用户既可以观看，也可以随时插话、追加条件或追问。系统通过这一过程帮助用户发现并澄清尚未明确表达的偏好，最终给出与这些偏好相符、理由可追溯的餐馆选择。

体验采用“小镇餐馆剧场”的表现形式：卡通人物、温暖的微缩场景、头顶对白气泡与有节奏的反应动画共同营造在场感。视觉参考来自《星露谷物语》与《星布谷地》的小镇生活氛围，以及多邻国角色的清晰轮廓和夸张表情；具体人物、服装、配色和动作采用原创设计。

本阶段由我们负责角色美术、3D 场景、骨骼与面部控制、动画资产、Three.js 播放接口和演示夹具；其他成员负责餐馆数据、检索筛选、多智能体协作及对话策略。首先完成需求、制作流程和 2D 设定审阅；获得用户明确批准后，才进入 Hyper3D 生成及后续绑定制作。

## 2. 设计目标与验证边界

- 核心体验假设：可见的推介与反驳能帮助用户表达偏好。黑客松演示可以证明流程可运行；是否减少真实选择困难，需要后续用户评估。
- 角色目标：用户在不读名字时，也能通过配色、服装、轮廓区分三人。
- 表演目标：当前发言人清晰，其他角色仍有合适的倾听和反应；表演不妨碍阅读和决策。
- 交互目标：用户可以打断、纠正条件、跳过表演，并查看餐馆事实依据。
- 推荐原则：中立引导智能体负责汇总。角色的表演强度与声音大小不直接决定排序。
- 事实边界：反驳针对有来源的价格、排队、距离、环境等差异。无法确认的事项用疑问或条件句表达。测试餐馆与对话一律标为虚构演示数据。

## 4. 美术方向

方向暂名“餐馆小剧场”。以温暖的奶油底色、收敛的饱和度、清晰的大色块和有辨识度的轮廓建立精致感。模型表面采用柔和的哑光材质，减少细碎布料、毛孔和复杂反光；配饰遵循大形体、少数量、便于绑定的原则。

比例目标约 3.5—4 头身；2D 草图存在比例偏差，批准后在 Blender 中锁定同一基础骨架与身体标尺。头部和眉眼提供主要表现力；嘴部不被胡子、领巾或道具遮挡。四指卡通手保留握持和摊手轮廓，首版整手驱动，不制作逐指表演。

| 配色用途 | 色值 | 使用方式 |
|---|---|---|
| 奶油白 | #F5ECDC | 背景、衬衣、气泡底色 |
| 深墨 | #29343A | 文字、鞋、阴影与视觉锚点 |
| 辣椒红 | #B94F45 | 四川老板娘外套和角色标识 |
| 姜黄 | #D2A44C | 四川角色围裙与少量点缀 |
| 玉石绿 | #447D6B | 粤菜老板衬衣和角色标识 |
| 灰鼠尾草绿 | #9BA98F | 地图植被、粤菜配色辅助 |
| 梅子紫 | #75628E | 法式主厨领巾、裤装和角色标识 |
| 淡黄铜 | #DCCB87 | 主厨小配饰和选择提示 |

这些色值是材质设计目标。生成图中的光照、阴影和纹理会改变像素颜色，不能直接视为精确色卡。

## 5. 三位角色的设计提案

### 四川餐馆老板娘

暂称“椒姐”，名字待确认。约 35—40 岁的成年女性，高发髻、利落短外套、姜黄色短围裙、深紫裤装，轮廓紧凑。身份来自经营者气质与衣着，不以地域口音或刻板夸张构成笑点。

表达节奏热情、直接、有感染力。推介时掌心打开、身体轻前倾；被质疑时先侧目挑眉，再用短促动作回应。招牌动作：轻叉腰、扬眉、朝观众摊开一只手。

可拆装配件：辣椒胸针、独立围裙结、小菜单牌。菜单牌首版可省略；参考图空手以降低建模与绑定难度。

### 粤菜馆老板

暂称“陈老板”，名字待确认。约 40—50 岁的成年男性，短侧分发型、单侧少量灰发、玉石绿短袖立领衬衣、奶油色围裙，身体较圆润。面部无胡须，保留嘴部可见性。

表达节奏温和而笃定，偏观察和补充事实。推介时动作幅度小；受到挑战后先停顿、抬眉，再平静回应。招牌动作：双掌轻合后单掌向上推出，像邀请入座。

可拆装配件：茶叶纹样口袋、茶杯、菜单牌。茶杯是后续手部挂点道具，不与手合并生成。

### 法式餐馆厨师长

暂称“主厨 Léon”，名字与性别设定可调整。当前概念选择成年男性：低矮厨师帽、奶油色双排扣厨师服、梅子紫领巾与裤装、少量黄铜色饰物。身形略高，嘴部无胡须遮挡。

表达节奏精确、克制，偶尔带一点戏剧感。介绍细节时先停顿再摊手；被指出预算问题时短暂尴尬，随后认可条件并说明取舍。招牌动作：小幅鞠躬后向两侧打开双掌。

可拆装配件：低厨师帽、独立领巾、摆盘托盘。首版不加入魔法元素，不使用高帽、长披风或复杂飘带。

## 6. 表情脑暴与首版优先级

表情是由眼、眉、面颊和嘴角控制量组合的预设，不是每种都制作一整段独立动画。

| 表情 | 演出用途 | 面部变化 | 优先级 |
|---|---|---|---|
| neutral 专注中性 | 等待、返回基态 | 眉眼放松，嘴闭合 | P0 |
| welcome 友好欢迎 | 出场、回答用户 | 轻微笑，眉稍抬 | P0 |
| confident 自信得意 | 展示本店优势 | 一侧嘴角抬起，轻扬眉 | P0 |
| curious 好奇倾听 | 用户补充偏好 | 双眉略抬，视线转向用户 | P0 |
| skeptical 怀疑侧目 | 听到对手夸张推介 | 单侧抬眉，眼球侧移 | P0 |
| surprised 意外 | 被指出关键差异 | 眼睛放大，眉抬高，O 嘴短闪 | P0 |
| embarrassed 尴尬 | 被拆台后回应 | 嘴角收紧，眉向内轻抬 | P0 |
| delighted 开心 | 被选中、赢得认可 | 微眯眼，笑容扩大 | P0 |
| thoughtful 思考 | 对复杂偏好权衡 | 视线偏上，嘴角收住 | P1 |
| amused 憋笑 | 温和的旁观反应 | 单侧嘴角上扬，短暂眯眼 | P1 |
| conceding 认可退让 | 承认不满足条件 | 眉放松，浅笑配点头 | P1 |
| disappointed 遗憾 | 未被选中 | 眉内侧微抬，轻收嘴角 | P1 |

切换提案：一般状态 180—250 ms 混合；惊讶约 100 ms 进入、200 ms 退出；被打断后约 150 ms 返回倾听；眨眼覆盖 80—140 ms。时间均待实机调整。没有针对所有表情两两转换制作动画的必要。

## 7. 场景与交互节奏

1. 用户说“想找一家适合聊天、不要太远的餐馆”。主持面板提取可见条件；缺失条件允许暂空。
2. 数据模块给出三个候选。地图上三个标记亮起，各角色依次从自己的位置出现。
3. 三条互不交叉的路线通往舞台站位，角色跑步后刹停。到位者转向用户，等待其余角色。
4. 每次只让一名角色发出完整语音；另外两人以侧目、抬眉、点头、小幅后仰做反应。
5. 先各自进行一轮 5—8 秒短推介，再由主持调度一到两次 3—5 秒质疑。对白长则分句；用户可随时插话。
6. 用户补充“今晚要认真聊天，最好人均 150 以内”。主持更新条件；三人针对这项条件回答，允许承认自身不合适。
7. 汇总卡列出用户偏好与餐馆证据。用户主动选择后，胜出角色庆祝，其余角色礼貌退场或降低视觉强调。

整段预设演示目标 60—90 秒，可缩短和跳过。角色热闹程度由调度器控制，避免三路同时说话或三个长气泡遮住脸。

## 8. 2D 审批与制作入口

本轮概念素材包含三人风格母版，以及每人一张四视角加八表情的设定表。它们用于决定风格、服装、身份、比例和表演幅度。图像生成可能产生袖口、口袋、纽扣、发型和朝向差异，需要人工审阅；不能声称像素级或几何级完全一致。

批准后，每位角色再制作 4 张独立、无拼版、无表情栏的单视图：正前 3/4、正面、侧面、背面。第一张作为材质与整体形象主要参考，其余提供结构约束；保持中性表情、相同 A-pose、统一光照与完整脚底。若不同视角互相矛盾，先修正参考，不直接提交生成。

用户批准仅针对选中的版本。当前没有获得进入 Hyper3D 生成的批准。
